# Pattern: Three-layer AI tooling architecture (Model / Hooks / Harness)

## Summary
Claude Code's hook surface (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SubagentStop, PreCompact, PostCompact, StopFailure, Notification) is a full lifecycle API. It enables a clean architectural separation: Model handles judgment/generation, Hooks handle policy/I/O/deterministic rules, Harness handles lifecycle/tools/transcripts. Rules that previously lived as "remember to..." instructions in prompts can migrate to hooks where they become deterministic, auditable, and versionable.

## Context
Discovered while shipping v6.9.0 (SessionStart hook for zero-Read context injection) and v6.10.0 (PreCompact + PostCompact hooks for compact-resilient markers). The pattern emerged from observing that the same problem (state survival across session boundaries) was unsolvable in the prompt layer but trivial in the hook layer.

## Details

**The three layers**:

```
MODEL    — judgment, generation, reasoning. Expensive, fuzzy, non-deterministic.
HOOKS    — policy, I/O, deterministic logic. Python, cheap, exact.
HARNESS  — lifecycle, tools, transcripts. Claude Code itself.
```

**Why this matters**:
- Rules don't compose well in natural language — model attention drifts, instructions get crowded out, "I forgot" failure mode is common.
- Hooks fire on state transitions deterministically. The model never sees the rule because the harness enforces it.
- Same model + different hook config = wildly different project behaviors (solo hacker autonomy vs enterprise audit/blockers). Analogous to Linux: kernel + userspace.

**Migration heuristic**: If a CLAUDE.md instruction starts with "always remember to..." or "never forget...", it's a hook candidate. The interesting design question stops being "how do I prompt this better?" and becomes "at which lifecycle event does this rule belong?"

**Examples already shipped**:
- SessionStart hook: injects navigator state, eliminates ~6 Read calls (v6.9.0)
- PreCompact hook: writes marker before any compact, manual or auto (v6.10.0)
- PostCompact hook: appends compact_summary to marker (v6.10.0)
- PostToolUse hook: monitors token usage (v4.6.0+)
- UserPromptSubmit hook: workflow enforcer (v6.4.0+, partial — currently warning, not blocking)

**Three properties this unlocks**:
1. **Auditability** — every tool call, prompt submit, session boundary becomes a logged event with structured data.
2. **Versionable policy** — workflow rules become Python files in git instead of prose in CLAUDE.md. Testable. Rollback-able.
3. **Per-project policy variation** — same model, different hook config = different behaviors. Composable without forking the model.

## Recommended Approach

When designing a new Navigator feature:
1. Frame the requirement first as "what should happen at lifecycle event X?"
2. If the requirement maps cleanly to a deterministic action at a hook event, write a hook.
3. If the requirement requires judgment (reading code, making decisions about content), keep it in the model layer.
4. Audit existing CLAUDE.md prose for "remember to..." patterns — those are migration candidates.
5. Use `${CLAUDE_PLUGIN_DIR}/hooks/...` paths so the hook ships with the plugin and updates atomically.
6. Always exit 0 from hooks unless intentionally blocking; never let a hook fail the user's request.
